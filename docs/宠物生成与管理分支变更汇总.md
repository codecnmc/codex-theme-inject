## 2. 总体结论

该分支已把项目从“主题注入工具”扩展为同时具备以下能力的完整桌面工具：

1. 管理、预览、导入、导出和安装 Codex 宠物。
2. 兼容 Codex V1/V2 及社区宠物 ZIP。
3. 将宠物与主题绑定，并随主题包一起导入导出。
4. 通过 AI 分阶段生成宠物基础形象和 9 个标准动作。
5. 支持断点恢复、后台生成、逐动作调优和确定性切图检查。
6. 降低多路生图、Base64 解码、切图和预览加载对 Codex 性能的影响。
7. 增加 GitHub Release 检查、下载、校验、安装、重启和失败回滚。
8. 发布时分别生成程序包和 `themes` 主题合集包。

这不是单一宠物页面改动，而是包含数据模型、ZIP 安全处理、AI 生成编排、图片处理、前端交互、主题打包、自动更新和发布流水线的一组跨模块改造。

## 3. 功能新增

### 3.1 宠物库

新增独立“宠物库”入口，提供：

- 宠物列表和待机缩略图。
- 9 个标准动作的动态预览。
- 安装或重新安装到 `CODEX_HOME/pets`。
- 导入、导出和删除宠物包。
- 编辑宠物名称和介绍。
- 将宠物绑定或取消绑定到当前主题。
- 单独调优某一个动作，确认后只替换对应动作行。
- 替换动作前保留原宠物备份，失败时恢复。

删除 Theme Inject 宠物库中的条目不会删除 Codex 已安装副本，避免库管理操作意外影响 Codex 当前环境。

### 3.2 社区宠物市场兼容

宠物包兼容范围包括：

- Codex V1：`1536x1872`，9 行标准动作。
- Codex V2：`1536x2288`，9 行标准动作加 2 行注视方向。
- ZIP 根目录包含 `pet.json + spritesheet.webp`。
- ZIP 单层子目录包含运行文件。
- 社区包缺少 `spriteVersionNumber` 时，根据 V1 图集尺寸自动识别。
- README、预览图和市场扩展字段可以随包存在。
- 修改名称和介绍时保留原社区市场字段。
- 导入后再次导出不会强制改写社区包的版本字段。

导入流程增加了 ZIP 路径、文件数量、解压总量、宠物 ID、清单路径、WebP 尺寸和图集结构校验，防止路径穿越、异常大包和不合法运行文件进入宠物库。

### 3.3 Codex 安装与备份

安装逻辑调整为：

1. 解析 `CODEX_HOME`，未设置时使用用户目录下的 `.codex`。
2. 先将宠物复制到临时安装目录。
3. 再次校验 `pet.json` 和 `spritesheet.webp`。
4. 已存在同 ID 宠物时先创建备份。
5. 通过目录替换完成安装。
6. 任一步骤失败时恢复旧宠物。

这解决了直接覆盖宠物目录可能留下半成品的问题。

### 3.4 主题绑定宠物

主题通过以下扩展字段记录配套宠物：

```json
{
  "themeInject": {
    "companionPetId": "pet-id"
  }
}
```

已实现：

- 宠物与当前主题绑定、解绑。
- 导出主题时自动包含 `pets/<pet-id>/pet.json` 和 `spritesheet.webp`。
- 导入主题时恢复宠物关联。
- 本地已有同 ID 宠物时不覆盖现有宠物。
- AI 生成宠物入库后自动绑定当前主题。

主题绑定只负责打包和关联，不会修改 Codex 当前选中的宠物。安装后仍需用户在 Codex 的宠物设置中选择，这是当前安全边界。

## 4. AI 宠物生成流程

### 4.1 从 AI 工作台迁移到宠物库

早期版本曾把宠物开关、宠物描述和生成结果放在 AI 主题工作台中。该分支后续完成了结构调整：

- AI 主题工作台只负责主题生成。
- 宠物生成迁移到“宠物库 -> 新建宠物”。
- 基础形象和动作生成仍在同一个新建宠物页面内。
- 页面使用“基础形象 / 动作生成”两个 Tab，避免工作台过度复杂。

### 4.2 基础形象

基础形象阶段只生成一张图片，不使用动作图片并发设置。

支持的输入优先级为：

1. 宠物基础形象专用参考图。
2. 主题 AI 工作台已有参考图。
3. 文字描述。

当用户明确上传宠物参考图时，会启用身份锁定：第一张图作为身份主依据，保留物种、脸型、眼睛、耳朵、毛色、标记、材质、左右不对称特征和已有道具，避免只参考风格却换成另一只宠物。

基础形象生成完成后先展示给用户确认，不会自动继续生成动作。用户可以：

- 按新描述重新生成基础形象。
- 保留基础形象，稍后再生成动作。
- 进入动作生成 Tab。
- 不使用 AI 基础图，直接上传现有基础形象生成动作。

### 4.3 动作生成

新生成宠物使用 V1 九行动作图集，不再生成注视方向。现有 V2 市场宠物仍可导入、安装和导出，但 Theme Inject 的动作管理界面只展示 9 个标准动作。

| 动作 | 固定帧数 | Codex 实际触发语义 |
| --- | ---: | --- |
| 待机 `idle` | 6 | 没有活动通知时持续播放 |
| 向右拖动 `running-right` | 8 | 用户把宠物向右拖动时 |
| 向左拖动 `running-left` | 8 | 用户把宠物向左拖动时 |
| 欢迎挥手 `waving` | 4 | 宠物首次出现或唤醒时 |
| 悬停反馈 `jumping` | 5 | 鼠标悬停在宠物上时 |
| 任务失败 `failed` | 8 | 任务失败或被阻塞时 |
| 等待输入 `waiting` | 6 | 需要用户输入或审批时 |
| 任务处理中 `running` | 6 | 任务正在思考或执行时，不是字面跑步 |
| 检查结果 `review` | 6 | 任务完成且结果尚未查看时 |

这些触发条件来自 Codex 当前实现。Theme Inject 只按真实语义生成动作，不修改 Codex 本体触发逻辑，因此“悬停反馈”仍由 Codex 的 `jumping` 状态触发。

### 4.4 逐动作提示词

动作生成页现在为每个动作提供独立提示词输入框，并显示固定帧数和真实触发条件。

用户可以：

- 手工描述某个动作的姿态、节奏和表情。
- 单独让 AI 生成某个动作的提示词。
- 一次让 AI 生成全部 9 个动作提示词。
- 在生成部分动作失败后，只继续未完成动作。

旧检查点中的全局 `actionPrompt` 仍可读取；新流程优先使用 `actionPrompts[动作槽位]`，保证旧数据可以恢复。

### 4.5 完整动作周期

提示词不再只写“做某个动作”，而是把固定帧数明确成时间线。例如 6 帧任务处理动作必须在 6 帧内完成开始、展开、完成、收回和回到起点。

统一增加以下约束：

- 动作必须在固定帧数内开始、发展并完成。
- 禁止在末尾开始第二个无法完成的动作周期。
- 最后一帧必须自然连接第一帧。
- 处理中不能生成为跑步。
- 左右拖动使用紧凑短步，禁止横向腾空或完全伸展。
- 其他静态状态固定脚部、躯干锚点和基线。

这主要解决“舔手只生成前半段”“动作乱晃”“循环突然断掉”等问题。

## 5. 生成恢复与后台任务

### 5.1 检查点与断点续跑

宠物生成增加持久化检查点，保存：

- 基础形象。
- 已完成动作行。
- 原始候选图和预览图。
- 名称、介绍、基础描述、逐动作提示词和参考图。
- 图片并发设置和生成阶段。

生成失败、用户中断、面板关闭或 Theme Inject 重启后，可以继续上次生成，不需要重新生成全部素材。

旧 V2 检查点中的注视方向素材会被忽略，只恢复新的 9 个标准动作，不删除已有检查点文件后再强制重来。

### 5.2 后台生成和进度提示

生成窗口现在允许关闭，任务继续在后台运行。顶部增加类似“灵动岛”的黑底白字生成状态，显示当前生成阶段和进度。

宠物创建页同时提供：

- 生成进度条。
- 已完成、生成中和失败项目。
- 中断生成。
- 返回宠物库并后台继续。
- 恢复基础形象或部分动作。

## 6. 图片生成、切图与装配优化

### 6.1 固定最终尺寸

所有动作生成提示词都以最终宠物单格 `192x208` 为生产目标，不再继承上传参考图的实际宽高、画布比例或留白。

动作图在切帧后会统一：

- 相机尺度。
- 躯干和头部视觉大小。
- 水平中心点。
- 脚部基线。
- 透明画布尺寸。

后端增加最小主体高度检查。动作因横向伸展而被缩得明显小于待机动作时，不再直接装配，而是进入自动修复重试。

### 6.2 多级切图策略

动作图支持以下切分路径：

1. 固定网格切割。
2. 按每行真实纯绿走廊自适应切割。
3. 兼容横向条带切割。

每个候选都会检查：

- 帧数是否正确。
- 主体是否贴住单格边缘。
- 相邻帧之间是否有足够纯绿间隔。
- 未使用网格是否保持纯绿。
- 是否存在空白帧或额外主体。
- 主体尺寸是否明显偏小。

切图失败时保留模型原始返回图供预览，并根据具体失败原因自动重试，不会只显示一个无法继续的错误。

### 6.3 抠图与清晰度

绿幕处理增加：

- 纯绿转透明 Alpha。
- 边缘绿色去色。
- 封闭绿缝和残留绿点清理。
- 隐藏 RGB 清理，避免缩放后重新出现绿色边缘。
- 透明素材统一居中和高质量 Lanczos 缩放。
- 最终图集显式使用无损 WebP 编码。

同时修复 JPG/JPEG 参考图预览失败，并为参考图、基础形象和动作候选生成浏览器可用的缩略图。

### 6.4 动作调优

宠物入库前和入库后都可针对单个动作重新生成：

- 当前基础形象或原宠物图集始终作为身份参考。
- 用户可补充动作提示词和参考图。
- 新候选只替换对应动作行。
- 原宠物先备份，其他动作保持不变。

## 7. 性能与稳定性优化

### 7.1 统一图片并发

主题图片生成和宠物动作生成共用统一图片并发设置与全局生成状态，避免主题 4 路加宠物 4 路后实际同时运行 8 路。

基础形象只生成一张，不展示无意义的并发设置；动作生成才使用统一并发数。

### 7.2 图片后处理队列

Base64 解码、图片解析、切图、抠图、缩放和编码改为后端排队处理，并放入阻塞任务线程，避免多个大图同时返回时争抢 Codex renderer 和 Rust 主任务资源。

生成请求可以并发等待网络，但 CPU 和内存密集型图片后处理受统一信号量限制，降低峰值内存和瞬时卡顿。

### 7.3 宠物预览缓存

宠物库预览调整为：

- 每个宠物资源只发起一个在途请求。
- 已加载 Data URL 进入缓存。
- 列表刷新时复用原资源 URL。
- 缩略图按单路加载，避免同时把多个完整图集转成 Base64。
- 删除或替换宠物时只失效对应缓存。

这减少了宠物库缩略图重复加载和打开面板时 Codex 整体卡住的问题。

### 7.4 注入与 DOM 观察

修复了主题运行时重复安装观察器、重复扫描 DOM、默认主题反复重载和标题图标持续刷新的问题。

注入流程增加目标页恢复、重复注入保护和更稳定的前台窗口处理，降低主题关闭后仍持续扫描导致的卡顿。

### 7.5 其他界面回归修复

分支同时处理了以下非宠物但由改造引起的回归：

- 恢复 Codex 原有代码语法高亮，不再把定义、函数和普通文本显示成同一颜色。
- 长状态文本自动换行，不挤压原有按钮。
- 宠物加载改为简洁旋转 Loading。
- 动作预览恢复逐帧播放。
- 删除宠物后立即关闭残留的下拉菜单。
- 宠物库入库后立即刷新右侧列表。

## 8. GitHub 自动更新

新增 `src/updater.rs`，提供：

- 查询固定 GitHub 仓库的最新正式 Release。
- SemVer 版本比较。
- 忽略草稿和预发布版本。
- 下载预期命名的 Windows x64 ZIP 和 `.sha256`。
- 流式下载、进度显示和取消。
- SHA-256 校验。
- ZIP 路径和额外可执行文件检查。
- 安装前备份当前 EXE。
- 使用辅助进程替换、重启和失败回滚。
- `target` 目录开发构建只允许检查，不允许自动替换。
- AI 生成任务运行时阻止强制安装更新。

更新只替换 Theme Inject 程序，不删除 `%LOCALAPPDATA%/ThemeInject` 下的主题、宠物、AI 设置、检查点和日志。

当前安全边界：发布资产已做 SHA-256 一致性校验，但尚未增加 Windows Authenticode 代码签名。

## 9. 发布流水线

`.github/workflows/package.yml` 已调整为在推送 `clean-version` 或手动触发时：

1. 从 `Cargo.toml` 读取版本。
2. 检查同版本 GitHub Release 尚不存在。
3. 执行 `cargo test --locked`。
4. 执行 `node scripts/check-runtime.mjs`。
5. 构建 Windows Release。
6. 生成 `theme-inject-windows-x64-v{version}.zip`。
7. 生成 `theme-inject-themes-v{version}.zip`，包含 `themes` 下全部主题 ZIP。
8. 为两个 ZIP 分别生成 `.sha256`。
9. 分别上传程序 Artifact、主题合集 Artifact 和 GitHub Release 资产。

这让用户可以只下载主题合集，而不必下载或解压程序包。

## 12. 需要评审确认的边界

### 12.1 新生成宠物改为 V1

新生成流程最终输出 9 行 V1 图集，原因是当前需求已明确去掉注视方向。V2 社区包仍可导入、安装和导出，但管理 UI 不再暴露两行注视方向。

需要确认这是否作为长期产品决策；如果未来恢复 V2，建议将“生成 V1 / 生成 V2”做成显式能力选择，而不是再次把方向行混入默认流程。

### 12.2 动作语义不能由 Theme Inject 改写

欢迎挥手、悬停反馈、拖动方向和任务状态的触发来自 Codex 本体。当前实现已让提示词匹配这些真实语义，但没有修改 Codex 代码，也不能把 `jumping` 改成其他事件触发。

### 12.3 AI 无法完全代替人工动作验收

程序可以确定性检查尺寸、帧数、透明度、边缘、中心和基线，但无法百分之百判断“舔手是否自然”“挥手是否像挥手”。当前保留基础图确认、动作预览和逐动作调优是必要的人工门槛。

### 12.4 旧设计文档存在过时内容

`docs/pet-generation-management-design.md` 记录的是较早的 V2 方案，仍包含注视方向和 AI 工作台宠物入口。当前实现已经迁移到宠物库并改为默认 V1 九行动作。

建议本汇总通过后，将旧设计文档标记为“历史方案”或同步更新，避免后续开发按过时流程继续实现。

### 12.5 合并基线

本分支与当前 `master` 没有共同祖先。建议采用以下方式之一：

- 将 `clean-version` 作为正式发布基线，直接合并本分支。
- 在新的发布分支上按顺序 cherry-pick 这 25 个提交。
- 先统一 `master` 与 `clean-version` 历史，再进行变基。

不建议直接强行合并两个无共同祖先的分支，否则会把历史重构和功能改动混在一次冲突处理中。

## 14. 建议验收顺序

1. 用 V1、V2 和社区嵌套 ZIP 各执行一次导入、预览、导出。
2. 将宠物安装到测试 `CODEX_HOME`，验证覆盖备份和 Codex 设置页可见。
3. 绑定宠物后导出主题，再在干净数据目录导入主题。
4. 分别测试“AI 生成基础形象”和“上传基础形象”。
5. 为 9 个动作生成独立提示词并完成动作生成。
6. 检查左右拖动动作与待机的主体尺寸、中心和基线。
7. 中途关闭面板、重启 Theme Inject，验证检查点恢复。
8. 对单个动作重新生成并确认其他动作未改变。
9. 使用测试 Release 验证检查、下载、SHA-256、安装重启和回滚。
10. 推送测试发布分支，确认程序 ZIP 和主题合集 ZIP 均出现在 Release。

完成以上流程后，该分支即可进入发布线整合评审。
